# Проверка исходной версии и подготовленные исправления

Проверено 28 октября 2026 года. Исходный коммит: `3fb62838a1fcb2efcf1135d3b82319beabee4114`.
Проверенная пользовательская копия: `v499168-cell/alice-gemini-serper-template`.

## Результат проверки исходников

В отслеживаемых файлах этой версии не обнаружены признаки фишинга, отправки секретов посторонним адресатам, обфускации или выполнения системных команд. Это ограниченная проверка исходного кода, не независимый аудит инфраструктуры и не гарантия безопасности будущих версий.

- Выполняемый обработчик: `api/index.js`.
- Сетевые назначения: только `generativelanguage.googleapis.com` и `google.serper.dev`.
- Ключ Google передаётся Google в `x-goog-api-key`; ключ Serper — Serper в `X-API-KEY`. Пользовательский вопрос и контекст передаются Gemini, поисковый запрос — Serper.
- В package.json нет внешних зависимостей и install/postinstall-скриптов; единственный npm-скрипт запускает встроенный тестовый раннер Node.
- Нет сторонней аналитики, фоновых рассылок, eval, shell-команд или запрашиваемых пользователем адресов для сетевых вызовов.
- `.env` и локальные секреты исключены из git.

## Найденные проблемы надёжности

1. Gemini ограничен 2500 мс; реальный развёрнутый обработчик возвращает общий fallback при прерывании запроса. Причина задержки API ещё не установлена.
2. Таймаут ошибочно распознаётся по message вместо name исключения.
3. История может превышать 1 КиБ session_state Яндекса (в тесте — 19 425 байт).
4. При ошибке Serper запрос о свежих данных отправляется Gemini без поискового контекста и без предупреждения.
5. Ошибки доступа, отсутствующей модели, неправильных параметров и JSON недостаточно различимы.
6. Публичный webhook не аутентифицирует отправителя. Сам по себе `ALICE_SKILL_ID` является лишь фильтром и не доказывает подлинность запроса.

## Подготовленная версия

- session_state ограничен 950 байтами UTF-8; слишком большие старые реплики удаляются, поэтому память пока краткая.
- Явное сообщение при недоступном поиске вместо неподтверждённого ответа.
- AbortError/TimeoutError обрабатываются по имени и состоянию сигнала.
- Ответы HTTP 400/401/403/404/429 различаются без публикации сырого сообщения провайдера.
- Редиректы сетевых запросов запрещены, чтобы не передавать API-ключи другому хосту.
- Исключены thought-части ответа модели.
- Проверка структуры запросов, ограничение длины вопроса, необязательный фильтр ALICE_SKILL_ID.
- `/api/diagnostics` по умолчанию отвечает 404. Для временного включения нужен отдельный DIAGNOSTICS_TOKEN длиной не менее 32 символов. POST проверяет только фиксированные вопросы к Google либо Serper, с лимитом 15 секунд. Никаких произвольных URL или пользовательских запросов. Ключи, ответы пользователя и сырые ошибки API не возвращаются. После диагностики удалить переменную DIAGNOSTICS_TOKEN.

## Serper и хостинг

Для Gemini 3.5 Flash-Lite вход/выход доступны на Free Tier, но Google Search grounding через API не доступен на этом тарифе. Поэтому Serper сохраняется как отдельный поиск. Для обычных вопросов поиск не используется. Источником служит таблица Google: https://ai.google.dev/gemini-api/docs/pricing .

Отдельный VPS не нужен для синхронной версии: её исполняет Vercel. Если API стабильно не укладывается в 4,5 секунды Яндекса, понадобится надёжная фоновая задача с постоянным хранилищем и выдачей результата по следующей реплике. В этой версии фоновое выполнение ещё не реализовано: сначала нужно измерить реальные API.

## Проверка

20 локальных тестов прошли, включая имитацию таймаута, ошибки Serper, недоступной модели, отсутствующего ключа поиска, ограничения размера стейта и закрытия диагностического маршрута. Живые проверки исправлений не выполнены: не выдан доступ подключения Vercel к команде проекта. Проверка Gemini в AI Studio не проверяет API-ключ, заданный в Vercel.
