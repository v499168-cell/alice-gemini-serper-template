# Проверка исходной версии и подготовленные исправления

Проверено 28 октября 2026 года. Исходный коммит: `3fb62838a1fcb2efcf1135d3b82319beabee4114`.
Проверенная пользовательская копия: `v499168-cell/alice-gemini-serper-template`.

## Результат проверки исходников

В отслеживаемых файлах этой версии не обнаружены признаки фишинга, отправки секретов посторонним адресатам, обфускации или выполнения системных команд. Это ограниченная проверка исходного кода, не независимый аудит инфраструктуры и не гарантия безопасности будущих версий.

- Выполняемый обработчик: `api/index.js`.
- Сетевые назначения: только `generativelanguage.googleapis.com` и `google.serper.dev`.
- Ключ Google передаётся Google в `x-goog-api-key`; ключ Serper — Serper в `X-API-KEY`. Пользовательский вопрос и контекст передаются Gemini, поисковый запрос — Serper.
- В package.json нет внешних зависимостей и install/postinstall-скриптов; единственный npm-скрипт запускает встроенный тестовый раннер Node.
- Нет сторонней аналитики, фоновых рассылок, eval, shell-команд или запрашиваемых пользователем адресов для сетевых вызовов.
- `.env` и локальные секреты исключены из git.

## Найденные проблемы надёжности

1. Gemini ограничен 2500 мс; реальный развёрнутый обработчик возвращает общий fallback при прерывании запроса. Живая проверка ключей дала HTTP 200: Gemini — 11 900 мс, Serper — 1 331 мс. Оба превышают исходные таймауты.
2. Таймаут ошибочно распознаётся по message вместо name исключения.
3. История может превышать 1 КиБ session_state Яндекса (в тесте — 19 425 байт).
4. При ошибке Serper запрос о свежих данных отправляется Gemini без поискового контекста и без предупреждения.
5. Ошибки доступа, отсутствующей модели, неправильных параметров и JSON недостаточно различимы.
6. Публичный webhook не аутентифицирует отправителя. Сам по себе `ALICE_SKILL_ID` является лишь фильтром и не доказывает подлинность запроса.

## Исправленная версия

- Обработка перенесена в Vercel Workflow, с быстрым HTTP-ответом Алисе и выдачей результата по «Дальше».
- Подписанный HMAC идентификатор привязан к session_id: чужой или изменённый идентификатор не позволяет прочитать результат другой сессии.
- Webhook требует отдельный ALICE_ACCESS_TOKEN не короче 32 символов; ALICE_SKILL_ID служит лишь дополнительным фильтром.
- Ключи поставщиков хранятся только в переменных Vercel; они не включены в Workflow-аргументы или результат.
- session_state содержит только идентификатор, подпись и флаг выдачи; ограничен 950 байтами UTF-8.
- Редиректы запросов поставщикам запрещены, thought-части модели исключены, ошибки API нормализованы без раскрытия сырых сообщений.
- Недоступный поиск не подменяется неподтверждённым ответом Gemini.
- Диагностический маршрут закрыт, пока не настроен отдельный DIAGNOSTICS_TOKEN; выполняет только фиксированные запросы, не возвращает ключи/сырой ответ.
- Добавлены Next.js и официальный Workflow SDK; версии зафиксированы package-lock.json. Вспомогательные zod и undici принудительно обновлены в overrides из-за уведомлений npm audit. Это увеличение цепочки зависимостей по сравнению с исходником.

## Serper и хостинг

У Gemini 3.5 Flash-Lite генерация доступна на Free Tier, но Google Search grounding через API не включён в него. Serper сохранён для явно поисковых вопросов; обычный вопрос не расходует поисковый запрос. https://ai.google.dev/gemini-api/docs/pricing

Отдельный VPS не нужен: Vercel исполняет webhook и надёжную фоновую задачу. Для Workflow действуют квоты и срок хранения; тексты вопросов, краткая история и ответы сохраняются у Vercel. Это не постоянный архив. Платный тариф не подключался.

## Проверки

20 исходных регрессионных тестов прошли. Добавлены тесты фонового диалога: повторные проверки без дублирования API, готовый ответ, продолжение контекста, изоляция сессий, восстановление после истечения задачи, авторизация webhook.
Живые ключи Google и Serper подтверждены HTTP 200. Локально прошли 25 тестов, Next.js production build и npm audit --omit=dev (0 известных уязвимостей).

Живая проверка тестовой версии (dpl_3kYQpaQiw3Mj5KDh8P33mjwv22hs):
- HTTP 200 health/приветствие, HTTP 401 для webhook без секрета.
- Полный цикл: задача → проверка «ещё готовится» → ответ Gemini «два плюс два — четыре».
- Следующий вопрос правильно восстановил имя Николай из серверного контекста.
- Поиск Serper + Gemini вернул официальный сайт Яндекса.
- Обработка запуска задачи — 265–433 мс; проверка/получение ответа — 70–186 мс; session_state — 123–124 байта.

OIDC подтверждён в заголовке запроса; переменная VERCEL_OIDC_TOKEN может отсутствовать. Проверять только process.env было неверно. После согласия пользователя включена проектная настройка OIDC.

Отдельно воспроизведена локальная несовместимость Dispatcher undici 8 со встроенным fetch Node: invalid onRequestStart method. Для сохранения исправленных зависимостей включён официальный режим WORKFLOW_NODE_HTTP=1. Он использует стандартные Node HTTP/HTTPS, а очередь — встроенный fetch без внешнего Dispatcher. Шифрование и проверка TLS сохраняются. У режима меньше транспортных оптимизаций/повторов; отказ не теряется молча, действует обработка сбоев Workflow.

Ограничения: проверка кода не доказывает безопасность инфраструктуры и будущих обновлений. При повторной транспортной доставке нового вопроса возможна повторная задача (дедупликация по message_id не реализована); повторные «Дальше» используют существующую задачу.
